# 简历描述与面试代码索引

## 可据实使用的项目描述

CampusTaste 校园食堂评价与排行榜后端，基于官方 FastAPI Full Stack 模板扩展；复用用户认证和基础工程结构，自行实现校园数据层级、菜品审核、评价评分、加权榜单及内容治理。

- 使用 PostgreSQL 行锁、唯一约束和事务维护评价明细与菜品评分聚合的一致性，使用真实数据库并发测试验证重复评分和并发改分。
- 使用 Redis 实现详情与榜单缓存、空值缓存、TTL 抖动、热点重建互斥、学校版本化榜单失效，以及 Lua 原子限流与刷新令牌轮换。
- 实现幂等点赞、举报审核、评价隐藏和管理审计，同事务维护治理状态与评分统计。
- 使用私有 MinIO、Celery 和 RabbitMQ 实现图片校验及缩略图任务，持久化任务状态，支持重试上限、补偿扫描和人工重试。

阶段 6 验收记录为 98 项后端测试通过、90% 语句覆盖率。使用 Locust 在本机只读场景验证 10/30 用户负载，实测条件与数据见 performance.md；不能将这个结果描述成系统最大吞吐量。CI 已编写并检查不等于已云端运行，没有性能提升对照或可用性指标。不能把模板自带登录、密码哈希和前端描述成从零实现。

## 面试追问与位置

| 追问 | 回答要点 | 代码位置 |
| --- | --- | --- |
| 登录怎样到数据库再返回 JWT？ | 表单输入、查询用户、校验哈希和状态、签发令牌 | `api/routes/login.py`、`crud.py`、`core/security.py` |
| Depends 解决什么问题？ | 会话生命周期、认证及公共权限；资源归属仍需业务检查 | `api/deps.py` |
| 模型与迁移为什么都要？ | 模型描述当前状态，迁移记录实际数据库演进 | `models.py`、`alembic/versions/` |
| 事务、锁、唯一约束各做什么？ | 原子提交、串行保护相关变更、最终防重 | `services/reviews.py`、`models.py` |
| 为什么读取加锁后还要刷新实体？ | SQLAlchemy 身份映射可能已有旧实例 | `services/reviews.py`、并发测试 |
| 榜单如何处理小样本？ | 先验权重与学校均分平滑，明确零评分和并列规则 | `api/routes/rankings.py` |
| 缓存更新为何不能保证强一致？ | 提交后删除仍有并发旧值回填窗口 | `services/cache.py` |
| Redis 锁为何不能代替数据库行锁？ | 前者约束缓存重建参与者，后者保护业务事务 | `services/cache.py`、`services/reviews.py` |
| 点赞为什么用 PUT 目标状态？ | 重复请求不反转结果，唯一约束防重复记录 | `services/governance.py` |
| 为什么先保存任务再发消息？ | Worker 必须查到记录，发送失败由补偿恢复 | `services/images.py`、`tasks.py` |
| 为什么不能保证消息只执行一次？ | 重投与崩溃窗口存在，用幂等结果及状态防护 | `tasks.py` |
| 如何定位一次请求？ | 请求 ID、JSON 日志、状态和耗时，不记录令牌 | `core/observability.py` |
| 压测数据能说明什么？ | 仅说明特定资源、数据和只读负载下的结果 | `loadtests/locustfile.py`、`scripts/run-loadtest.py` |

面试时先说业务问题，再说具体保证、验证方法和限制，不只罗列组件名称。
